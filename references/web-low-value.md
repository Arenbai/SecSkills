# 低价值/噪音类漏洞速查（默认不报）

> 本文件合并原 6 个第三梯队专项（CORS/CRLF/Host头/缓存投毒/请求走私/GraphQL）及常见噪音项。
> **总原则：这些是技术特性或配置问题，不是漏洞。检测后默认跳过，不写进报告。**
> 唯一例外：能演示完整利用链并造成**实际数据泄露 / 账户劫持 / 横向影响其他用户**，按对应危害等级重新归类报告（如 GraphQL→SQLi 按 SQLi 报告）。

## 1. 快速判定表（命中即跳过）

| 项目 | 一句话本质 | 默认处理 |
|------|-----------|---------|
| 明文传输 / HTTP 未跳转 HTTPS | 部署架构问题 | 跳过，不检测 |
| 缺少安全响应头（CSP/HSTS/X-Frame-Options 等） | 浏览器加固配置 | 跳过，摘要一行带过 |
| Cookie 缺 HttpOnly/Secure/SameSite | 会话加固配置 | 跳过 |
| 自签名证书 / 弱 TLS / 弱加密套件 | 运维配置 | 跳过 |
| CORS Origin 反射 / `*` | 跨域策略配置 | 跳过（例外见 §2） |
| 开放重定向 | 业务功能特性 | 跳过（例外见 §2） |
| OPTIONS/TRACE 方法开启 | 协议特性 | 跳过 |
| 用户名枚举 / 响应差异 | UX 设计 | 跳过 |
| 详细错误堆栈（无密钥/凭据） | 调试配置 | 跳过 |

## 2. 六类第三梯队：检测入口 + 报告门槛

### 2.1 CORS
- **检测**: `curl -H "Origin: https://evil.com" -I <target>/api/user` → 看 `Access-Control-Allow-Origin` 是否反射 + `Allow-Credentials: true`
- **报告门槛（必须同时满足）**: ① ACAO 反射任意 Origin 且允许凭据 ② 实际跨域 fetch 窃取到敏感数据（Cookie/Token/隐私API响应）③ 给出完整 PoC 页面
- 仅 Origin 反射、仅 `*`（无凭据）→ 不报

### 2.2 CRLF 注入
- **检测**: 参数注入 `%0d%0aX-Test:1` → 响应头出现 `X-Test:1`
- **报告门槛**: 注入响应头实现 **XSS（%0d%0a%0d%0a<html>...）有弹窗证据** 或 **Set-Cookie 会话固定并实际劫持会话**
- 仅 `%0d%0a` 回显 → 不报

### 2.3 Host 头注入
- **检测**: 改 `Host: evil.com` 发请求 → 响应/重置邮件中是否使用注入的 Host
- **报告门槛**: **密码重置链接劫持成功** — 重置邮件中的链接域名被替换为攻击者域名，且用该链接可实际重置受害账户
- 仅 Host 反射在响应体 → 不报

### 2.4 缓存投毒
- **检测**: 加非键化头 `X-Forwarded-Host: evil.com` → 响应反射且 `X-Cache: HIT` / `Age` 递增
- **报告门槛**: 投毒后的缓存副本**被其他真实用户命中**并触发 XSS/重定向 — 需提供两次不同会话的验证证据
- 仅存在非键化头反射（无缓存命中证明）→ 不报

### 2.5 HTTP 请求走私
- **检测**: 发 `CL.TE` / `TE.CL` 歧义请求（`Transfer-Encoding: chunked` + `Content-Length` 冲突），观察响应差异/超时；工具: Burp HTTP Request Smuggler
- **报告门槛**: 证明**劫持了其他用户的请求/会话**或**窃取到跨用户数据**，仅时间差异/504 不算
- 注意: 误报率极高，扫描器告警一律手动复现后再判断

### 2.6 GraphQL
- **检测**: 端点 `/graphql` `/api/graphql`；内省 `{"query":"{__schema{types{name}}}"}`
- **报告门槛**: 通过 GraphQL 实际达成以下之一 → **按达成的高危漏洞归类报告**：
  - SQL 注入（带数据回显）→ 按 SQLi 报
  - IDOR/越权读到他人敏感数据 → 按越权报
  - Batching 爆破 OTP/密码成功 → 按认证缺陷报
- 仅内省开启 / 仅列出 schema → 不报

## 3. 开放重定向（补充）

- **检测**: `?url=` `?next=` `?redirect=` 参数改为 `https://evil.com` → 302 跟随
- **报告门槛**: 仅当可链接到**凭据窃取** — 如 OAuth `redirect_uri` 开放重定向导致 `code`/`token` 外泄到攻击者域名，且有完整验证
- 裸开放重定向 → 不报
